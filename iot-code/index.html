4. SQLite і синхронізація

DeviceRepository.cs, рядки 74–86 · LoadAsync

Репозиторій читає незастосовані зміни. Якщо API відповідає, оновлює кеш у SQLite. При втраті зв’язку бере список із SQLite. В обох випадках PendingOverlay накладає зміни з черги, щоб користувач бачив останню локальну правку.

LoadAsync · PR №89 · кеш

DeviceRepository.cs, рядки 91–112 · SaveAsync

Для пристрою з незавершеними змінами наступну правку теж кладу в чергу, щоб зберегти порядок. Для іншого запису пробую надіслати створення або оновлення одразу. Якщо під час цього пропадає зв’язок, QueueSaveAsync зберігає правку локально.

SaveAsync

SyncEngine.cs, рядки 54–76 · обробка черги

Операції відправляються по черзі. Після створення тимчасовий ID замінюється серверним. Успішну операцію позначаю завершеною, постійну помилку переношу до відхилених. На тимчасовій помилці записую спробу і припиняю прогін. Ця операція лишається в черзі.

Цикл обробки · Три результати

OfflineSyncTests.cs, рядки 67–81 · тест обриву

Тест готує зміни для двох пристроїв. Перша проходить, на другій тест імітує мережевий збій. Assert.False перевіряє, що прогін перервався. Assert.Single перевіряє поточну чергу, а останнє твердження звіряє ID другого пристрою і одну спробу.

Спільний API

Виконати simulator/out-of-range
