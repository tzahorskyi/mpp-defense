Код для показу

Підключення до API. lab4/MauiProgram.cs:11 (рядки 11–14).

var api = DeviceInfo.Platform == DevicePlatform.Android ? "https://10.0.2.2:7080/" : "https://localhost:7080/";
builder.Services.AddSingleton(new HttpClient(DevHandler())
    { BaseAddress = new Uri(api), Timeout = TimeSpan.FromSeconds(15) });
builder.Services.AddSingleton<ApiClient>();

Указую адресу API з ЛР 3. Для Android 10.0.2.2 веде з емулятора до сервера на комп’ютері.

Той самий клієнт використовує localhost у Windows і спеціальну адресу хоста в Android-емуляторі. Адресу налаштовую в одному місці. Екрани входу й завдань працюють через спільний ApiClient.

Оновлення списку. lab4/ViewModels.cs:75 (рядки 75–78).

bool? done = Filter switch { 1 => false, 2 => true, _ => null };
var items = await api.GetTasksAsync(Search, done, Sort switch { 1 => "-priority", 2 => "title", _ => "due" });
Tasks.Clear();
foreach (var t in items) Tasks.Add(t);

Передаю пошук, фільтр і сортування в API. Коли приходить відповідь, замінюю список на екрані. Це видно, коли вводжу «лр».

Екран прив’язаний до списку у ViewModel. Після відповіді сервера колекція оновлюється, а список перемальовується. Кнопки й поля керують запитом, а отримані дані відображаються на екрані.

1. Enter → відкривається застосунок. Спочатку спробуй неправильний пароль, потім увійди з даними з термінала.

З неправильним паролем API повертає 401, а застосунок показує помилку під формою. Після успішного входу застосунок отримує токен і використовує його, щоб завантажити список завдань.

Після входу зверху видно ім’я користувача. Нижче — його завдання, терміни й пріоритети. Цей список завантажився з API, тому його вміст залежить від облікового запису, під яким я увійшов.

2. В емуляторі → список і пошук. Введи лр і натисни кнопку пошуку на клавіатурі емулятора. Покажи фільтр чи сортування, потім очисть пошук.

Пошук звузив список до завдань, де «лр» є в назві або описі. Коли змінюю фільтр чи сортування, застосунок робить новий запит до API і оновлює список.

Можу перемкнутися з «Невиконані» на «Усі». Тоді з’являються й виконані завдання. Сортування за пріоритетом змінює порядок карток. Так на одному екрані перевіряю, що всі параметри запиту працюють у клієнті.

Показ результату

3. В емуляторі → створення й редагування. Створи завдання, відкрий його, увімкни «Виконано» і збережи. За потреби видали свайпом.

Нове завдання з’явилося у списку після збереження на сервері. У деталях після редагування видно статус «Виконано». Якщо підтвердити видалення, завдання зникає зі списку.

На формі також можна перевірити помилку. З назвою «x» сервер повідомляє, що назва закоротка, і форма лишається відкритою. Після виправлення й збереження повертаюся до списку та відкриваю створене завдання.

4. Enter у терміналі → сервер вимкнено. Потягни список униз в емуляторі. Після показу натисни Enter у терміналі для завершення.

Після зупинки API я тягну список униз. Застосунок пробує повторно завантажити дані й показує «Сервер недоступний». Так користувач бачить, чому оновлення не відбулося.

Під час цього показу сам застосунок продовжує працювати. Зникає можливість отримати свіжі дані від API, і застосунок виводить конкретну причину. Цей випадок відрізняється від помилки входу, коли сервер доступний і відповідає на запит.

Дякую за увагу.
