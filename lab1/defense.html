Доброго дня. Я Тарас Загорський, група ІПЗ-31. Перша лабораторна — консольний менеджер завдань. У коді є моделі проєкту, завдання й тега, а EF Core працює з базою через спільний контекст.

Код для показу

Вибір бази. lab1/Program.cs:8 (рядки 8–15).

var provider = builder.Configuration["Provider"] ?? "Sqlite";
var cs = builder.Configuration.GetConnectionString(provider);
_ = provider switch
{
    "Sqlite" => builder.Services.AddDbContext<AppDb, SqliteDb>(o => o.UseSqlite(cs)),
    "Postgres" => builder.Services.AddDbContext<AppDb, PostgresDb>(o => o.UseNpgsql(cs)),
    _ => throw new InvalidOperationException($"Невідома СУБД: {provider}")
};

Параметр Provider визначає, який драйвер підключити. В обох випадках решта програми працює зі спільним AppDb.

Запит зі списком завдань. lab1/Program.cs:53 (рядки 53–56).

var important = db.Tasks
    .Where(t => !t.Done && t.Priority >= 2)
    .OrderByDescending(t => t.Priority).ThenBy(t => t.Due)
    .Select(t => new { t.Title, t.Priority, t.Due, Project = t.Project.Name });

Цей запит вибирає невиконані завдання з пріоритетом від двох і сортує їх. Саме його результат видно в рядках під [Read] після обох запусків.

1. Enter → конфігурація. Покажи ключ Provider і два рядки підключення.

Базу обираю параметром Provider. SQLite працює з файлом, PostgreSQL — через сервер у Docker.

2. Enter → SQLite. У виводі покажи [Create], [Read], [Update] і [Delete].

Програма створила два проєкти, п’ять завдань і три теги. Фільтр знайшов три невиконані завдання із пріоритетом від двох. «ЛР1 EF Core» позначено як виконане, одне домашнє завдання видалено, і залишилося чотири.

Показ результату

3. Enter → PostgreSQL і порівняння. Покажи ті самі блоки для PostgreSQL. За потреби прокрути до запуску SQLite.

Змінив тільки провайдера. У PostgreSQL після фільтрації ті самі три завдання і після видалення теж залишилося чотири. У звіті є обидва запуски та порівняння в підрозділі 4.1.

4. Enter → таблиці й міграції. Покажи назви таблиць. На паузі з бонусним запуском Linux натисни Ctrl+C, якщо показ завершено.

Схема містить проєкти, завдання, теги й таблицю зв’язків. EF Core перекладає наші запити в SQL, а типи колонок і міграції залежать від бази.
